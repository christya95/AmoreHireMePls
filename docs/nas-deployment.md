## 2. Network and attach plan

Two supported placements; both use the same database and user.

**A. App on the Mac (or any tailnet host), database on the NAS.** Works today without SSH:

```bash
# .env (non-secret)
AMORE_MONGODB_URI=mongodb://100.90.96.81:27017/?directConnection=true
AMORE_MONGODB_AUTH_SOURCE=amorehiremepls
# secrets via config/op.env.example -> .env.references
op run --env-file .env.references -- uv run amore setup-db
op run --env-file .env.references -- uv run amore web
```

**B. App containers on the NAS.** The Mongo container publishes 27017 on the NAS host, so the app reaches it through the host gateway (Compose already sets `extra_hosts: host.docker.internal:host-gateway`):

```bash
AMORE_MONGODB_URI=mongodb://host.docker.internal:27017/?directConnection=true
AMORE_MONGODB_AUTH_SOURCE=amorehiremepls
```

Alternative for B: join the Mongo container's Docker network (`docker network ls` on the NAS; GymBro's is `amoregymbro-nas_default`) and use the container name, which keeps traffic off the host interface:

```yaml
networks:
  default:
    name: amoregymbro-nas_default
    external: true
```

Hardening to ask for (not done by this project): a Tailscale ACL that allows `tcp:27017` on `dxp4800plusjoss` only from Joss's devices, and no LAN/WAN publishing of 27017. Keep `AMORE_BIND_HOST=127.0.0.1` for the dashboard on the NAS and reach it over the tailnet with `ssh -L 8790:127.0.0.1:8790` or a Tailscale Serve rule.

## 3. Secrets (1Password, unattended)

Same pattern as AmoreGymBro: a read-only service account scoped to the `AmoreHireMePls` vault. Store the token at `/volume1/docker/amorehiremepls/op_token` (`chmod 600`, owned by the deploy user) and start services through `op run`:

```bash
export OP_SERVICE_ACCOUNT_TOKEN="$(cat /volume1/docker/amorehiremepls/op_token)"
op run --env-file .env.references -- docker compose up -d web worker
```

`.env` on the NAS holds only non-secret settings. `.env.references` is a copy of `config/op.env.example` (OpenAI key, dashboard password, session secret, Mongo app user). Items present in the vault on 2026-11-04: `OpenAI API Key`, `NAS MongoDB App User`. Still to create: `Dashboard Password`, `App Session Secret` (and `SMTP` only if email outreach is enabled).

## 4. Build and run

```bash
rsync -a --exclude runtime --exclude .env --exclude .git ./ nas:/volume1/docker/amorehiremepls/
ssh nas 'cd /volume1/docker/amorehiremepls && docker compose build && op run --env-file .env.references -- docker compose up -d web worker'
ssh nas 'curl -s http://127.0.0.1:8790/health'
```

SSH on the NAS is normally off (UGOS auto shutoff after ~30 min); enable it in UGOS before the rsync and let it close again afterwards. The image is based on `mcr.microsoft.com/playwright/python:v1.64.1-noble` and includes `libreoffice-writer`; both services run as uid 10001 with all capabilities dropped, `no-new-privileges`, the vendored Playwright seccomp profile, 1.5 CPU / 1536 MB limits, json-file log rotation, and a persistent `/data` volume. Chromium and LibreOffice were verified inside this hardened container on the Mac (`docs/capability-map.md`).

## 5. Browser sessions

The worker runs headless. Sign in to job sites on the Mac with `uv run amore browser login <site> <url>` and copy `runtime/private/sessions/<site>.json` to the NAS volume (`/data/private/sessions/`) over SSH. Expired sessions surface as `handoff` interrupts.

## 6. Tracker clone

On the NAS, `amore tracker clone` needs git credentials for `christya95/job-application-records`. Use a fine-grained GitHub token limited to that repository, injected as `GIT_ASKPASS` through 1Password, or keep `AMORE_TRACKER_PUSH_ENABLED=false` and let the Mac push from its own clone (`local_only` items stay visible until pushed).

## 8. Running the test suite against the NAS

The fixtures accept a fixed throwaway database so a `readWrite`-only user works (collections are dropped between tests instead of the database):

```bash
printf 'U=op://AmoreHireMePls/NAS MongoDB App User/username\nP=op://AmoreHireMePls/NAS MongoDB App User/password\n' > /tmp/app.env
op run --env-file /tmp/app.env -- sh -c 'AMORE_TEST_MONGODB_URI="mongodb://$U:$P@100.90.96.81:27017/amorehiremepls_test?authSource=amorehiremepls&directConnection=true" AMORE_TEST_MONGODB_DATABASE=amorehiremepls_test uv run pytest -m mongo -q'
rm /tmp/app.env
```

The app user needs `readWrite` on `amorehiremepls_test` and `amorehiremepls_test_restored` (backup test) for the duration; grant with the root session, revoke afterwards. 2026-11-04 result: 55 passed in ~10 minutes.
